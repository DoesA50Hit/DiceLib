Home

DiceLib (mod id dicelib) is a library of building blocks for NeoForge 1.21.1 mods: who an ability reaches, damage and projectiles, taking control of mobs, knockback, zones, healing, dashes and teleports, props, timing, effects and player animations, spoken lines and dialogue, holograms and mob panels, a command framework and body parts. It adds no content of its own. It needs PlayerAnimationLib and GeckoLib, and nothing else.

The examples are written for an imaginary mod called mymod. The full example classes are in DiceLib's examples source set, where the build compiles them, and docs/build_guide.py copies them into these pages. The short snippets are not compiled by the build. If the guide and the code disagree, trust the code.

Setup

DiceLib is a NeoForge 1.21.1 mod (dicelib) that other mods build on. It needs PlayerAnimationLib and GeckoLib. It does not need a UI library or an effect library.

Adding it to a project#

A project uses the built jar from its own libs/ folder.

  1. In DiceLib, gradle.properties lists the projects to copy into, separated by ;:
dicelib_deploy_to=../My Mod/libs;../Other Mod/libs
  1. ./gradlew deployJar builds DiceLib and copies dicelib-<version>.jar and its sources jar into each libs/ folder, removing older DiceLib jars there first.
  1. The project depends on it and on the two libraries DiceLib needs, because a jar in libs/ doesn't bring its dependencies with it:
dependencies {
    implementation fileTree(dir: 'libs', include: 'dicelib-*.jar', exclude: '*-sources.jar')
    implementation "com.zigythebird.playeranim:PlayerAnimationLibNeo:1.1.6+mc.1.21.1"
    implementation "software.bernie.geckolib:geckolib-neoforge-1.21.1:4.9.3"
}
  1. Its neoforge.mods.toml names DiceLib as a required dependency, ordered AFTER, so that DiceLib is set up before the project's constructor runs.
  1. A project that writes commands with the Command Framework compiles with -parameters, so arguments can take their names from the Java parameters:
tasks.withType(JavaCompile).configureEach { options.compilerArgs << '-parameters' }

After a change to DiceLib, run deployJar again and rebuild the project. In IntelliJ, attaching the sources jar to the library shows DiceLib's code and comments.

Targeting

Targets finds the entities an ability reaches. It searches along the caster's eye line or in an area, a line, a cone or a chain, and it can filter the result to allies or enemies. The caster can be a player or a mob.

Eye line#

MethodReturns
eyeLine(caster, range)a HitResult: the nearest entity on the eye line (EntityHitResult), else the block that stops the line (BlockHitResult), else a miss
lookedAt(caster, range, relation)the living entity looked at, when alive and of the relation, otherwise null

Blocks in the way hide whatever is behind them. The ray stops at the first block with a collision shape, and fluids don't count. Spectators, the caster, and entities that can't be picked are skipped.

The line uses the caster's view direction, the head rotation for living entities. A real player's head follows the camera, so the line points where the player looks.

// an enemy in front of the caster within 16 blocks
LivingEntity enemy = Targets.lookedAt(caster, 16, Targets.Relation.NON_ALLIES);
if (enemy != null) enemy.hurt(caster.damageSources().mobAttack(caster), 5f);

An ability that also works on blocks uses the full hit result:

HitResult hit = Targets.eyeLine(caster, 20);
switch (hit) {
    case EntityHitResult entityHit -> {
        Entity struck = entityHit.getEntity();
        struck.igniteForSeconds(3);
    }
    case BlockHitResult blockHit when blockHit.getType() == HitResult.Type.BLOCK -> {
        BlockPos above = blockHit.getBlockPos().relative(blockHit.getDirection());
        if (caster.level().getBlockState(above).isAir()) caster.level().setBlockAndUpdate(above, Blocks.FIRE.defaultBlockState());
    }
    default -> {
        // a miss: hit.getLocation() is the end of the line
    }
}

This steps to where the caster looks, stopping half a block short of the first wall:

Vec3 end = Targets.eyeLine(caster, 12).getLocation();
Vec3 back = caster.getLookAngle().scale(-0.5);
caster.teleportTo(end.x + back.x, end.y + back.y, end.z + back.z);

Movement › Teleports does the same with safe landing spots and effects.

Areas#

MethodReturns

around(origin, radius, relation)living entities within radius blocks of the origin's position
around(origin, point, radius, relation)living entities whose feet are within radius of a point, the relation seen from origin. Never the origin
touching(origin, point, radius, relation), touching(level, point, radius, predicate)the same two searches by the hitbox instead of the feet: anyone whose hitbox comes within radius of the point, so a big mob whose side is in reach counts
around(level, point, radius, predicate)every living entity within radius of a point that the predicate lets through, for searches with no caster
cylinder(origin, base, radius, height, relation)everyone standing in an upright cylinder: radius around base along the ground, from base up height blocks
projectilesAround(origin, point, radius, relation)projectiles in flight near a point, judged by who shot them. NON_ALLIES are those fired by anyone not allied with origin, and those with no shooter

targetable(entity)whether an ability can pick the entity at all: alive, not a spectator, not in the dicelib:untargetable tag
allyRule(rule)adds a way for two entities to be allies. Register once at startup

Relation is ALLIES, NON_ALLIES or ANY. "Allied" follows vanilla's isAlliedTo: the same scoreboard team, a tamed animal and its owner, or anything a mod adds to that check. The check runs both ways. It then runs again for whoever owns each of the two (a projectile's shooter, a summon's caster), so two summons of one caster are allies, and a summon is an ally of its caster's team-mates.

Vanilla doesn't count players without a team as allies. If your mod has its own parties, add a rule:

Targets.allyRule((a, b) -> a instanceof Player x && b instanceof Player y && Parties.same(x, y));

Every search skips entities that aren't targetable. The entity type tag dicelib:untargetable lists armour stands and DiceLib's entity copies. Add your own scenery entities to it from a datapack (data/dicelib/tags/entity_type/untargetable.json).

// every non-ally within 5 blocks takes 4 damage
for (LivingEntity target : Targets.around(caster, 5, Targets.Relation.NON_ALLIES)) {
    target.hurt(caster.damageSources().mobAttack(caster), 4f);
}

// heal every ally within 8 blocks, the caster too
Heals.heal(caster, caster, 2f);
for (LivingEntity ally : Targets.around(caster, 8, Targets.Relation.ALLIES)) {
    Heals.heal(caster, ally, 2f);
}

Lines, cones and chains#

MethodReturns
line(caster, range, width, relation)everyone the eye line passes within width blocks of, nearest first, up to the first block in the way
cone(caster, range, angle, relation)everyone within range the caster can see, within angle / 2 degrees of where it looks (angle is the full width)
chain(caster, first, count, hop, relation)first, then the nearest not-yet-hit entity within hop blocks of the last one, count total. The caster is never included
chain(caster, first, count, hop, relation, also)the same, hopping only to those the predicate also lets through

segment and blockStop are for beams that don't start at the caster's eyes, such as one from a turret or from the sky.

// a beam from 20 blocks up, straight down to the ground where the caster looks
Vec3 spot = Targets.eyeLine(caster, 24).getLocation();
Vec3 sky = spot.add(0, 20, 0);
Vec3 ground = Targets.blockStop(caster, sky, spot.add(0, -20, 0));
for (LivingEntity target : Targets.segment(caster, sky, ground, 0.5, Targets.Relation.NON_ALLIES)) {
    target.hurt(caster.damageSources().mobAttack(caster), 5f);
}
// a lance that pierces everyone in a line
for (LivingEntity target : Targets.line(caster, 16, 0.5, Targets.Relation.NON_ALLIES)) {
    target.hurt(caster.damageSources().mobAttack(caster), 6f);
}

// a 90 degree cone of steam, 8 blocks long
for (LivingEntity target : Targets.cone(caster, 8, 90, Targets.Relation.NON_ALLIES)) {
    target.hurt(caster.damageSources().mobAttack(caster), 3f);
}

// a ricochet between up to 4 enemies within 6 blocks of each other
LivingEntity first = Targets.lookedAt(caster, 32, Targets.Relation.NON_ALLIES);
if (first != null) {
    for (LivingEntity target : Targets.chain(caster, first, 4, 6, Targets.Relation.NON_ALLIES)) {
        target.hurt(caster.damageSources().mobAttack(caster), 4f);
    }
}

For any other shape, call inBox and filter the result. These searches are built the same way.

This puts two players on a scoreboard team, as vanilla's /team does, which makes them allies:

Scoreboard scoreboard = server.getScoreboard();
PlayerTeam team = scoreboard.getPlayerTeam("party");
if (team == null) team = scoreboard.addPlayerTeam("party");
scoreboard.addPlayerToTeam(player.getScoreboardName(), team);
scoreboard.addPlayerToTeam(target.getScoreboardName(), team);
boolean allied = Targets.isAlly(player, target);   // true

Control#

Control takes a mob over for a while, for a charm or a mind control. It works on any Mob, including ones vanilla can't tame, and it doesn't touch vanilla taming, so the mob is unchanged when the control ends.

// the zombie fights for the caster for 30 seconds
if (!Control.of(caster, zombie).life(600).start()) {
    // it can't be controlled, or another mod refused
}
CallDoes
Control.of(owner, mob)control to set up, then start(). start() returns false when it is refused
life(ticks)how long it lasts (600 by default)
allowBosses()lets it work on bosses
onEnd((mob, end) -> ...)runs when it ends, with EXPIRED, RELEASED, REPLACED or GONE (the mob died or was removed). Not kept through a restart
Control.release(mob)ends it now
Control.isControlled(mob), owner(mob), remaining(mob)whether it is controlled, by whom, and for how many more ticks
Control.controlledBy(owner)the loaded mobs in the owner's level that it controls
Control.canControl(owner, mob, bosses)whether start() would accept the mob

Three things refuse control:

  • The mob's type is in the c:bosses entity type tag, which holds the wither and the ender dragon. allowBosses() skips this check.
  • The mob's type is in the dicelib:no_tame entity type tag. Add types to it from a datapack (data/dicelib/tags/entity_type/no_tame.json).
  • The mob carries the tag noTame, as given by /tag @e[...] add noTame.

Nothing in code bypasses the last two.

While a mob is controlled it drops its target and can't target its controller or the controller's allies. Once a second it picks up the controller's fight, going after whoever hurt the controller or whoever the controller hurt, and when it has nothing to fight it walks back to the controller. Targets.isAlly treats it as the controller's, so your abilities count it as an ally. A mob with no attack only follows. Mobs that choose targets through a brain, such as piglins and wardens, stop attacking the controller but may not join its fights.

Control is saved with the mob and counts game time. Control.ControlEvent.Start fires before it is taken and can be cancelled, for an immunity or a resist roll. Control.ControlEvent.End fires after it ends, with the reason.

Knockback

Knockback shoves, pulls and leashes. Every push scales by the target's knockback resistance, so at 1 the target doesn't move, and a push on a player reaches that player's client. A shove along the ground (away, toward, along, push) posts vanilla's LivingKnockBackEvent first, so a mod that cancels or changes a sword's knockback does the same to these. pull and leash run every tick and don't post it.

CallDoes
Knockback.away(target, from, back, up)away from from along the ground by back, and up by up (roughly blocks per tick)
Knockback.toward(target, to, strength, up)toward to, which pulls the target in
Knockback.along(target, direction, strength, up)along direction on the ground (its up and down is ignored), and up by up. Use it for wind, or any shove that has no source point
Knockback.push(target, velocity)a push along any velocity
Knockback.pull(entity, point, strength)any entity, projectiles included, drawn toward a point, faster the further away (at most strength blocks a tick), slowing what it was doing. Called every tick, it makes a vortex. Nothing within half a block moves
Knockback.leash(target, anchor, radius)called every tick: past radius from anchor, the leash stops the way out and draws the target back, harder the further past
// a shockwave: every non-ally within 4 blocks is thrown 1.2 back from the caster and 0.4 up
for (LivingEntity target : Targets.around(caster, 4, Targets.Relation.NON_ALLIES)) {
    Knockback.away(target, caster.position(), 1.2, 0.4);
}

// a vortex for 3 seconds where the caster looks
Vec3 centre = Targets.eyeLine(caster, 16).getLocation();   // the block or entity looked at, or the end of the line
// Every tick for 60 ticks. The task belongs to the caster and stops if they die.
Scheduler.repeat(caster, 1, 60, (owner, tick) -> {
    for (LivingEntity target : Targets.around(owner, centre, 8, Targets.Relation.NON_ALLIES)) {
        Knockback.pull(target, centre, 0.3);   // at most 0.3 blocks a tick, faster the further out they are
    }
});

Movement › Dashes moves the caster itself.

Zones

Zones makes an area that lasts and pulses, such as a healing spring or a burning circle. Zones.at(level, centre, radius) sets one up at a point (the middle of its floor), and Zones.on(entity, radius) sets up one that follows the entity and ends with it. Each pulse plays the zone's effect stretched to its radius, plays its sound, and runs its rules on whoever stands in it. The first pulse happens immediately. start() returns the Scheduler task for the rest, and cancelling it ends the zone early. Zones are not saved, so a server stop ends them.

public final class MendingSpring {
    // A healing spring at the caster's feet for 5 seconds. Call it from an item's use or a boss's attack.
    public static void place(LivingEntity caster) {
        if (!(caster.level() instanceof ServerLevel level)) return;   // zones run on the server
        Zones.at(level, caster.position(), 4)             // a circle 4 blocks in radius
                .every(20)                                // one pulse a second
                .lasting(100)                             // for 5 seconds. The first pulse is immediate
                .fx(MyMod.id("spring"), Fx.Fallback.ring(ParticleTypes.SPLASH, 4))   // played at each pulse
                // Each pulse heals the caster and every ally in the circle by 1. What doesn't fit under their max
                // health stays as absorption for 100 ticks.
                .onAllies(caster, (ally, pulse) -> Heals.of(caster, ally, 1).overheal(100).heal())
                // Everyone else in it is slowed. 30 ticks is longer than the gap between pulses, so the slow holds for
                // as long as they stand there.
                .onEnemies(caster, (enemy, pulse) -> enemy.addEffect(new MobEffectInstance(MobEffects.MOVEMENT_SLOWDOWN, 30, 1), caster))
                .start();
    }

    private MendingSpring() {
    }
}
CallDoes
every(ticks)ticks between pulses (default 20)
times(pulses)the total number of pulses, counting the immediate first one (default 1)
lasting(ticks)one pulse now and one every every ticks until ticks have passed
follow(entity)moves with the entity, at its feet, and ends when it dies or leaves
height(blocks)an upright cylinder from the floor up, instead of a ball
fx(id, fallback), sound(sound, volume, pitch)played at the middle of the floor each pulse (Effects and Animations)
onEnemies(caster, (target, pulse) -> ...)each pulse, on everyone in it not allied with caster. Never the caster
onAllies(caster, (ally, pulse) -> ...)each pulse, on caster and its allies standing in it
on(predicate, (entity, pulse) -> ...)each pulse, on everyone in it the predicate lets through
onPulse((centre, pulse) -> ...)each pulse, with where the zone is now, for anything that isn't a living entity, such as blocks or items
onEnter(entity -> ...)for each entity found in the zone at a pulse that wasn't there the pulse before, the first pulse included
onExit(entity -> ...)for each entity gone since the pulse before, and for everyone still inside at the last pulse. Not when the task is cancelled or the followed entity goes
hitboxes()counts anyone whose hitbox reaches into the ball, not only feet inside it. A zone with a height still goes by the feet
center(), inside()where it is and who stands in it, at any time

onEnter and onExit are checked once per pulse, so they can be up to every ticks late. They run for every entity in the zone, allies and enemies alike, so filter inside the callback if that matters.

// a slowing mire for 10 seconds: slowed while inside, freed on the way out
Zones.at(level, centre, 4)
        .every(5)                 // checked 4 times a second, so stepping in or out is noticed quickly
        .lasting(200)
        // onEnter runs once for each entity that steps in. -0.4 makes it 40% slower.
        .onEnter(entity -> While.modifier(entity, Attributes.MOVEMENT_SPEED, MyMod.id("mire"), -0.4, AttributeModifier.Operation.ADD_MULTIPLIED_TOTAL, true))
        // onExit runs when it leaves, and for everyone still inside when the zone ends
        .onExit(entity -> While.modifier(entity, Attributes.MOVEMENT_SPEED, MyMod.id("mire"), 0, AttributeModifier.Operation.ADD_MULTIPLIED_TOTAL, false))
        .start();

The pulse number counts from 0. A zone measures from the feet, so a ball reaches radius blocks up as well as out. Allies and enemies follow Targeting's relations.

Damage

Hits deals damage and records where it came from, as Heals does for healing (Healing). Shots fires projectiles that hit through it. Both are in combat and run on the server.

Hits#

Every hit has a source. The source is the caster, or something that belongs to them such as a projectile, a prop or a summon. DiceLib finds the living entity behind the source and makes it the attacker, so a hit from a floating sword counts as its owner's hit and its owner gets the kill. The damage goes through vanilla's hurt, so armour, enchantments, hurt time and the damage events all apply.

// 6 damage that counts as the caster's hit
Hits.of(caster, target, 6)
        .knockback(0.8, 0.3)      // shoved 0.8 back from the caster and 0.3 up
        .fx(MyMod.id("slash"), Fx.Fallback.burst(ParticleTypes.CRIT, 0.4f, 8))   // played on the target if the hit lands
        .hit();                   // deals it, and returns what the target lost

// The source can be a prop. The sword's owner is then the attacker and gets the kill.
Hits.of(sword, target, 4).type(DamageTypes.MAGIC).hit();
CallDoes
Hits.of(source, target, amount)a hit to set up, then hit()
Hits.hit(source, target, amount)the same in one call
times(multiplier)scales the amount
type(damageType)the damage type. Left out, it is a player's attack when the attacker is a player, a mob's attack for any other attacker, and magic with no attacker
throughHurtTime()lands even while the target is still red from the last hit. Use it for hits that come several times a second
knockback(back, up)a shove away from the source when it lands, on top of the small one vanilla gives
fx(id, fallback), sound(sound, volume, pitch)played on the target when it lands
onHit(dealt -> ...)runs with what the target lost
hit()hits, and returns what the target lost in health and absorption. 0 when cancelled, blocked or still in hurt time

Events#

Both are posted on NeoForge.EVENT_BUS. getEntity() is the entity that was hit.

EventWhen
Hits.HitEvent.Hitbefore anything is hurt. Cancel it, or change the amount with setAmount
Hits.HitEvent.Landedafter, with what the target lost. Not posted when the hit didn't land

getSource() is the entity the hit came from, and getAttacker() is the living entity behind it.

// a quarter of what the wearer deals comes back as health
@SubscribeEvent
static void onLanded(Hits.HitEvent.Landed event) {
    // getAttacker is the living entity behind the hit, also when a prop or a shot of theirs dealt it
    if (event.getAttacker() instanceof Player player && wearsLeechRing(player)) {
        Heals.heal(player, player, event.getAmount() / 4);   // getAmount is what the target actually lost
    }
}

Only hits made through Hits post these. Vanilla's own damage events cover everything else.

Shots#

Shots fires a projectile for an ability. A shot is an entity with no model that the server flies along a line, an arc or after a target. Players see its trail. It hits whatever its path passes, by its owner's relations (Targeting), and its damage goes through Hits, so the owner is the attacker.

// a bolt from the caster's hand that goes through two enemies and bursts where it ends
Shots.from(caster, BodyPoints.hand(caster, true), caster.getLookAngle().scale(1.5))   // 1.5 blocks a tick
        .range(24)                // ends after 24 blocks
        .pierce(2)                // passes through two enemies and stops in the third
        .damage(5)                // each one takes 5, with the caster as the attacker
        // a shot has no model, so the trail is what players see
        .trail(MyMod.id("bolt"), Fx.Fallback.line(ParticleTypes.ELECTRIC_SPARK))
        // onEnd runs once however the shot ends, with the shot still at that spot
        .onEnd((shot, end) -> Fx.at(level, MyMod.id("burst"), shot.position(), 1, Fx.Fallback.burst(ParticleTypes.CRIT, 0.4f, 12)))
        .fire();                  // nothing flies until fire()

// a slow missile fired straight up that turns toward its target
Shots.from(caster, BodyPoints.chest(caster), new Vec3(0, 0.5, 0))
        .homing(target, 12)       // turns up to 12 degrees a tick
        .life(100)                // gives up after 5 seconds if it never arrives
        .damage(8)
        .fire();
CallDoes
Shots.from(owner, from, velocity)a shot from a point, flying velocity blocks per tick. Shots.from(level, null, from, velocity) makes one with no owner, which hits anyone
range(blocks), life(ticks)how far it flies (32) and how long it lasts at most (200)
gravity(perTick)makes it fall, for an arc. An arrow's is 0.05
homing(target, degreesPerTick)turns toward the target each tick, keeping its speed
width(blocks)how close its path must pass a hitbox to hit (0.25)
pierce(count)how many entities it passes through before the one that stops it (0)
relation(relation)who it hits, seen from its owner (NON_ALLIES). Never the owner
throughBlocks()blocks don't stop it
damage(amount)hurts each entity it hits, through Hits
trail(id, fallback), trail(id, fallback, every)a line effect along the stretch it flew, every tick or every every ticks
onHit((shot, target) -> ...)runs for each entity it hits, after the damage
onBlock((shot, blockHit) -> ...)runs when a block stops it
onTick(shot -> ...)runs every tick it flies, after it has moved, for particles or a sound a trail can't give
onEnd((shot, end) -> ...)runs once when it ends, with the shot still at that spot
fire()adds it to the level

Shots.End is RANGE, EXPIRED, BLOCK, HIT (it ran out of pierce) or STOPPED (shot.stop() was called). A flying shot can be redirected with shot.velocity(vector). Shots are never saved.

Healing

Heals heals an entity and records where the heal came from. It also gives absorption and has a call for cheating death. It is in combat and runs on the server.

Heals#

Heals.heal(source, target, amount) heals the target and records the source, which is the entity the heal came from. The source can be the caster, something of theirs such as a projectile, a prop or a summon, or null when the heal has no source. Send all of your mod's healing through it, so that anything listening for heals knows where each one came from. Movement

Dashes moves a caster along a path over a few ticks. Teleports moves an entity in one jump, to an exact position, to the nearest safe spot, or as a blink. Both are in motion and run on the server.

Dashes#

A dash carries the caster for a few ticks, for a lunge or a pounce. Each tick it sets the caster's motion (and tells a player's client), keeps the fall from counting, and at the end stops the caster where it is. start() takes the first step immediately and returns the Scheduler task for the rest. A caster has one dash at a time, so starting another interrupts the one that is running. Dashes.cancel(caster) stops a dash on the spot and Dashes.dashing(caster) asks whether one is running.

public final class ExampleLunge {
    // A short dash along the ground that cuts each enemy in the way once.
    public static void lunge(LivingEntity caster) {
        // flatLook is the way the caster looks with the up and down taken out, one block long.
        // Scaled by 0.9 it becomes the dash's speed in blocks a tick.
        Vec3 velocity = BodyPoints.flatLook(caster).scale(0.9);
        Dashes.along(caster, velocity, 6)                 // 6 ticks at 0.9 is a bit over 5 blocks
                // runs once for each non-ally the caster passes through
                .onHit(Targets.Relation.NON_ALLIES, hit -> hit.hurt(caster.damageSources().mobAttack(caster), 4))
                .start();                                 // the dash only begins here
    }

    // A leap at the enemy the caster looks at, with a heavy blow on arrival. False when there is no one to leap at,
    // so the ability can skip its cooldown.
    public static boolean pounce(LivingEntity caster) {
        LivingEntity target = Targets.lookedAt(caster, 12, Targets.Relation.NON_ALLIES);   // within 12 blocks
        if (target == null) return false;
        Dashes.to(caster, target, 1.2, 20)                // 1.2 blocks a tick, given up after 20 ticks
                // runs when the caster touches the target, and the dash ends there
                .onContact(hit -> {
                    // hurt returns false when the damage was blocked, and then there is no shove
                    if (hit.hurt(caster.damageSources().mobAttack(caster), 8)) {
                        Knockback.away(hit, caster.position(), 0.8, 0.3);   // 0.8 back from the caster, 0.3 up
                    }
                })
                .start();
        return true;
    }

    private ExampleLunge() {
    }
}

Teleports#

Every teleport goes through Teleports.MoveTeleport, an EntityTeleportEvent, so anything listening for ender pearls and chorus fruit hears about these too, and can change the target or cancel. Teleports.to(entity, target) and Teleports.blink(entity, distance) set one up, and go() sends it. go() returns where the entity landed, or empty when the teleport was refused or cancelled. An entity that is riding something gets off first, as with an ender pearl.

Exact or safe#

A plain to(...).go() lands exactly where it is sent, even inside a wall or in mid-air. safe() asks for a safe spot instead: one the entity fits in, with ground under it, and with no fluid and nothing from the dicelib:unsafe_to_land block tag in or under it. The tag holds fire, campfires, lava, magma, cactus, berry bushes, wither roses, powder snow, cobwebs and portals, and a datapack can add more. The search tries the target first, then whole blocks outward along x and z and up and down, nearest first, and lower before higher on a tie.

// to a marked spot
Teleports.to(caster, marked)
        .safe(4, 3)               // the nearest safe spot within 4 blocks along x and z and 3 up or down
        .orAnyway()               // or exactly the marked spot when there is none
        .facingToward(target.getEyePosition())   // turned to look at the target on arrival
        .go();

// Straight down onto the ground under a point in the air. safe(0, 8) only searches up and down.
Optional<Vec3> landed = Teleports.to(caster, point).safe(0, 8).go();   // empty when there was no ground within 8 blocks

FloatingItem#

A FloatingItem shows any item as its item model at full brightness, always in one of four poses:

Both sides compute where an orbiting, row or fanned object belongs from the game time and its holder, so it keeps up with a moving holder without waiting on the server. An item with a holder is removed when its holder is.

Flying#

fly(owner, velocity, range, hitsEntities, relation, onHit, stickTicks) sends it straight along velocity (blocks per tick) for range blocks. With hitsEntities it stops at the first living entity matching relation to owner (never the owner). It always stops at blocks. Then onHit runs once with whatever it hit (null for a block or the end of its range) and where it stopped, and it sticks there, pointing the way it flew, for stickTicks before fading. By default a stuck item stays where it stopped, so it hangs in the air if the entity it hit walks away. Call sticksToTarget() to keep it in that entity and move it along. stuckIn() returns the entity.

Formation#

A Formation keeps a caster's floating items in named groups. The READY group hangs around them, and keep tops it up or trims it to a count and places each one, every tick. An ability can hold other groups for a while, such as a shieldwall. A caster's items vanish when the caster dies or leaves.

A formation only handles how the items look. The number of items a caster has, like anything else that must be saved, belongs in saved data such as an attachment or the player's persistent data. Read the count from there and pass it to keep. After a restart the formation is rebuilt from that count.

@EventBusSubscriber(modid = MyMod.MODID)
public final class ExampleSwords {
    // The fan. Each new object in it is an iron sword, and one that vanishes plays this effect.
    private static final Formation FAN = Formation.of(caster -> new ItemStack(Items.IRON_SWORD)).vanishFx(MyMod.id("sword_fade"));
    // How many swords are ready. The count lives in the player's saved data, so the fan is rebuilt from it after a
    // restart. The Formation only draws the swords and is never saved.
    private static final String READY = "mymod_swords_ready";
    private static final int MAX = 5;

    // Every tick: a player with a nether star in the off hand has their ready swords fanned out behind them.
    @SubscribeEvent
    static void onTick(PlayerTickEvent.Post event) {
        if (!(event.getEntity() instanceof ServerPlayer player)) return;
        CompoundTag data = player.getPersistentData();
        if (!data.contains(READY)) data.putInt(READY, MAX);          // a new player starts with all five
        boolean shown = player.getOffhandItem().is(Items.NETHER_STAR) && !player.isInvisible();
        int count = shown ? data.getInt(READY) : 0;                   // keeping 0 makes the swords vanish
        // keep adds or removes swords until there are `count`, then places each one with the lambda.
        // Here each sword takes its slot in a fan 0.9 blocks long that starts a little above the middle of the back.
        FAN.keep(player, count, (sword, slot, slots) -> sword.fan(player, slot, slots, 0.9f, player.getBbHeight() * 0.62f));
    }

    // Throws one sword where the player looks. It is ready again 4 seconds later. False when none is ready.
    public static boolean send(ServerPlayer player) {
        CompoundTag data = player.getPersistentData();
        if (data.getInt(READY) <= 0) return false;
        data.putInt(READY, data.getInt(READY) - 1);                   // one fewer in the fan from the next tick
        // 80 ticks later the count goes back up. The task belongs to the player and is dropped if they leave.
        Scheduler.after(player, 80, owner -> {
            CompoundTag saved = owner.getPersistentData();
            saved.putInt(READY, Math.min(MAX, saved.getInt(READY) + 1));
        });
        // take pulls the last sword out of the fan, so keep stops moving it and it can fly off
        FAN.take(player).fly(player,
                player.getLookAngle().scale(1.6),                     // 1.6 blocks a tick
                24,                                                   // for up to 24 blocks
                true, Targets.Relation.NON_ALLIES,                    // it stops at the first non-ally
                (hit, at) -> {
                    // hit is null when a block stopped it or it ran out of range
                    if (hit != null) hit.hurt(player.damageSources().playerAttack(player), 5);
                },
                12);                                                  // then it stays stuck there for 12 ticks
        return true;
    }

    private ExampleSwords() {
    }
}

Tether.spawn(level, TetherLook.CHAIN, caster.position())

// a chain that slows the target for 5 seconds unless someone breaks it

AnimatedProp#

An AnimatedProp is a GeckoLib model that appears, plays one animation and leaves. It has no AI. The model id ns:name points at assets/ns/geo/prop/name.geo.json, assets/ns/animations/prop/name.animation.json and assets/ns/textures/prop/name.png. Put the key moment (a bite, a slam) on a cue timed to the animation's frame.

// a serpent that comes up 2.5 blocks short of the target and bites on tick 12
Vec3 dir = target.position().subtract(caster.position()).multiply(1, 0, 1).normalize();   // toward the target, along the ground
Vec3 from = target.position().subtract(dir.scale(2.5));
AnimatedProp.spawn(level, MyMod.id("stone_serpent"), from, AnimatedProp.yawToward(from, target.position()))   // facing the target
        .animation("animation.stone_serpent.strike")   // played once, then held on its last frame
        .life(30)                 // removed after 30 ticks
        .reach(4)                 // the model is up to 4 blocks long, so it is drawn while any of it is in view
        // The server can't read the animation, so the bite is timed by hand to match it.
        .on(12, serpent -> {
            if (target.isAlive()) target.hurt(caster.damageSources().mobAttack(caster), 8);
        });

Timing and State

Scheduler runs code later, CasterState keeps values per caster, Cooldowns times abilities, While holds modifiers while a condition lasts, and TempEnchants puts enchantments on for a while. All five are in state.

Scheduler#

Scheduler runs code later on the server, either once after a delay or a set number of times on an interval. Abilities use it for anything delayed, like a blast a second after the cast or a hit every second for five seconds.

CallRuns
Scheduler.after(ticks, () -> ...)once, ticks ticks from now
Scheduler.after(entity, ticks, entity -> ...)the same, skipped if the entity is gone by then
Scheduler.repeat(interval, times, run -> ...)times times, the first one interval ticks from now. run counts from 0
Scheduler.repeat(entity, interval, times, (entity, run) -> ...)the same, stopping early once the entity is gone

"Gone" means removed from the world (killed, discarded, unloaded, a player who logged out) or, for a living entity, dead. Every call returns a Scheduler.Task with cancel() and isDone().

It counts server ticks, so pausing a singleplayer world pauses it as well. after(20, ...) runs 20 full ticks later, and any delay under 1 counts as 1.

A blast that lands a second after the cast, on whatever the caster aimed at:

LivingEntity target = Targets.lookedAt(caster, 16, Targets.Relation.NON_ALLIES);
if (target != null) {
    // One second later. The task is tied to the target, so it is skipped if the target is gone by then.
    Scheduler.after(target, 20, marked -> {
        marked.hurt(caster.damageSources().mobAttack(caster), 6);
        ((ServerLevel) marked.level()).sendParticles(ParticleTypes.EXPLOSION, marked.getX(), marked.getY() + 1, marked.getZ(), 1, 0, 0, 0, 0);
    });
}

For damage over time, this one hits every second for five seconds and stops early if the target dies:

static void burn(LivingEntity caster, LivingEntity target) {
    // Every 20 ticks, 5 times. run counts from 0, and the task stops by itself if the target dies.
    Scheduler.repeat(target, 20, 5, (burning, run) -> {
        burning.hurt(caster.damageSources().onFire(), 2);
        if (run == 4) burning.clearFire();                   // the last of the five
    });
}

If an action throws, DiceLib logs the exception and drops that task. Other tasks keep running.

A delayed action runs no matter what happened in the meantime, so it should check what it depends on. Here the second hit only lands if the caster still holds the staff:

target.hurt(caster.damageSources().mobAttack(caster), 3);
// Tied to the caster this time, so the second hit is dropped if the caster dies within those 2 seconds.
Scheduler.after(caster, 40, later -> {
    if (!later.getMainHandItem().is(MyItems.STAFF.get())) return;   // and it needs the staff still in hand
    if (target.isAlive()) target.hurt(later.damageSources().mobAttack(later), 5);
});

Tasks live in memory only, so stopping the server drops them. For something that must survive a restart, such as a curse that ends in an hour, save the end time with your own data and check that.

CasterState#

A CasterState keeps what an ability holds per caster and never saves, such as the chain it holds or the golems it commands. It empties itself when the caster dies, leaves the level (logs out, changes dimension, is unloaded), or the server stops. It runs onClear on whatever it drops, so the props it held go away. Make one per kind of value as a static field. Server side only.

public final class ExampleHolds {
    // One chain per caster, for an ability that holds someone. CasterState forgets the chain when the caster dies or
    // leaves and runs the lambda on it, which pulls the chain back in so none is left hanging in the world.
    public static final CasterState<Tether> HOLDS = CasterState.create((caster, chain) -> chain.retract());
}
// a new hold replaces the old one, and onClear pulls the old one back in
ExampleHolds.HOLDS.put(caster, Tether.spawn(level, TetherLook.CHAIN, caster.position()).from(caster, true).to(target).extend(4));
Tether held = ExampleHolds.HOLDS.get(caster);
// let go: the chain is pulled back in
ExampleHolds.HOLDS.remove(caster);
CallDoes
put(caster, value)sets it. The previous value is dropped through onClear
get(caster), getOrCreate(caster, supplier), has(caster)
remove(caster)takes it out and runs onClear
take(caster)takes it out without onClear, when the ability hands it to something else
CasterState.clearAll(caster)clears every store for that caster, for your own reset

A value that must survive a restart belongs in saved data, such as an attachment or an item component.

Cooldowns#

Cooldowns keeps cooldowns on any entity, each under an id. Use one id per ability or item, or share an id between several abilities. Cooldowns are saved with the entity and kept through death. They count game time, so they don't run down while the server is off.

public static final ResourceLocation FIREBALL = MyMod.id("fireball");

static void cast(LivingEntity caster) {
    if (!Cooldowns.tryStart(caster, FIREBALL, 100)) return;   // not ready yet
    // ... the fireball
}
CallDoes
Cooldowns.tryStart(entity, id, ticks)starts it and returns true when it is ready. While it is still running it returns false and changes nothing
Cooldowns.start(entity, id, ticks)starts it, replacing one already running. 0 or less clears it
Cooldowns.ready(entity, id), remaining(entity, id)whether it is ready, and the ticks until it is
Cooldowns.progress(entity, id, partialTick)0 the moment it starts, 1 when ready, for drawing
Cooldowns.reduce(entity, id, ticks)makes it ready that many ticks sooner, for a refund on a kill or a haste effect
Cooldowns.clear(entity, id), clearAll(entity)ends one, or all of them
Cooldowns.all(entity)the ones still running, by id

Starting, reducing and clearing are server side. Reading also works on the client. Each player's own cooldowns are synced to them, so your HUD can call Cooldowns.progress(player, FIREBALL, partialTick) without sending anything itself. Other entities' cooldowns are not synced.

While#

While is for effects that should apply only while a condition holds, such as while sprinting. Call its methods with the condition every tick, or whenever the condition may have changed. They change the entity only when the condition's value changed. When the rule stops applying, call them once more with false.

CallDoes
While.modifier(entity, attribute, id, amount, operation, on)the modifier on while on, off otherwise
While.scaledModifier(entity, attribute, id, amount, operation)keeps a modifier at amount, replacing it if it changed. 0 removes it (attack speed per combo hit)
While.effect(entity, effect, amplifier, on)keeps an effect up while on, no particles. The same effect from a potion is left alone
// boots of haste: faster while sprinting with them on
@SubscribeEvent
static void onTick(PlayerTickEvent.Post event) {
    if (!(event.getEntity() instanceof ServerPlayer player)) return;
    boolean on = player.isSprinting() && player.getItemBySlot(EquipmentSlot.FEET).is(MyItems.HASTE_BOOTS.get());
    // Called every tick with the condition. It adds the modifier when `on` turns true and removes it when it turns
    // false, and does nothing on the ticks in between.
    While.modifier(player, Attributes.MOVEMENT_SPEED, MyMod.id("haste_boots"), 0.1, AttributeModifier.Operation.ADD_MULTIPLIED_BASE, on);
}

Temporary enchantments#

TempEnchants puts an enchantment (or Unbreakable) on an item for a while. The item remembers its previous state in the dicelib:temp_enchants component and gets it back when time is up. DiceLib checks the items in a player's inventory and the items lying on the ground every second, and a container's items when a player opens it. An item kept anywhere else, such as another mod's slots, changes back once it reaches one of those places. Anvils and grindstones refuse these items, so nobody can make a temporary enchantment permanent or grind it into XP. The tooltip shows what is temporary and for how long.

Holder<Enchantment> sharpness = level.registryAccess().registryOrThrow(Registries.ENCHANTMENT).getHolderOrThrow(Enchantments.SHARPNESS);
long until = level.getGameTime() + 400;
TempEnchants.raise(sword, sharpness, 3, until);   // at least Sharpness III for 20 seconds
TempEnchants.unbreakable(sword, until);

A second raise on the same enchantment never lowers the level or shortens the time. The item keeps the higher level and the later end time, and when time is up it goes back to the level it had before the first raise.

TempEnchants.revert(stack, now) takes back whatever has run out by game time now, and TempEnchants.isTemporary(stack) asks whether anything on the item is temporary.

Effects and Animations

Fx plays visual effects by id from the server, BodyPoints gives the points on an entity they start from, and PlayerAnims plays player animations. All three are in visual.

Effects#

An effect is an id such as mymod:spell/flare, sent from the server to every client within 64 blocks (Fx.RANGE). DiceLib itself draws no effect files. Each client hands the id to the effect players its mods added (Effect players), and the first one that knows the id plays it. Every call also gives a fallback, a vanilla particle pattern that the client draws when no effect player plays the id. This means an effect shows something before its file exists, and on a client with no effect library.

CallPlays
Fx.at(level, id, point, scale, fallback)at a point, scaled evenly by scale (zone effects are made 1 block wide and played at their radius)
Fx.at(level, id, point, scale, yaw, fallback)the same, turned to face yaw (degrees, like an entity's). Make the effect facing +Z
Fx.on(entity, id, scale, fallback)at the entity's feet, following it while it plays
Fx.line(level, id, from, to, fallback)from one point to another. An effect made 1 block long along +X is turned and stretched to fit
Fx.line(level, id, from, to, thickness, fallback)the same, scaled by thickness across the line. A 1 block line turns an effect to face along it without stretching, for a circle that faces where someone looks

Fx.Fallback.burst, ring, sphere, column and line make the fallback patterns. Their sizes are in blocks, and scale stretches only what an effect player draws. An effect played on an entity doesn't rotate with it, so something that must face an entity's travel plays as a line instead. Effects are one-shot. They can't loop and can't be removed once started, so for something that lasts, play a short effect again at an interval (Sounds and repeated effects).

// a ring at the target's feet, 6 blocks across
Fx.at(level, MyMod.id("bloom"), target.position(), 6, Fx.Fallback.ring(ParticleTypes.HAPPY_VILLAGER, 6));

Fx.hideOnYourself(id) marks an effect played on an entity that would fill the screen of the one it surrounds, such as a shell or a dome. That player's client skips it in first person, and everyone else still sees it. Call it once at startup, from either side.

Effect players#

An effect player turns ids into something drawn, usually with an effect library. Add one at client setup with ClientFx.addPlayer. Players get each effect in the order they were added. One returns true when it played the effect, or false to pass it on. When none plays it, the fallback does.

A sketch of one backed by Photon, whose effect files live at assets/<ns>/fx/<path>.fx:

ClientFx.addPlayer((level, entity, payload) -> {
    // false passes the effect on to the next player, or to the fallback particles when there is none
    if (!FXHelper.listAllFX().contains(payload.id())) return false;
    FX fx = FXHelper.getFX(payload.id());
    if (entity != null) {
        EntityEffectExecutor executor = new EntityEffectExecutor(fx, level, entity, EntityEffectExecutor.AutoRotate.NONE);
        executor.setScale(new Vector3f(payload.scale(), payload.scale(), payload.scale()));
        executor.start();
    } else {
        new BlockEffectExecutor(fx, level, BlockPos.containing(payload.from())).start();
    }
    return true;
});

The payload carries everything the call gave: id(), entity() (-1 for none), from() and to() (equal except for lines and thrown effects), scale(), yaw() (NaN for unturned) and fallback().

Thrown effects#

Fx.fly(level, id, from, to, ticks, arc, fallback, onArrive) throws an effect. The effect id (1 block long along +X, facing its travel, like a line effect) plays wherever it is each tick, rising arc blocks at the middle, and onArrive runs on the tick it lands. One packet starts the throw and each client steps it, so a long throw costs no more than a short one. Every tick plays a new copy, so keep the effect short, like a streak or a glint. Fx.travel(from, to, speed) returns the ticks something moving at speed blocks per tick takes.

// a mote of light arcing from the target to the caster, healing when it lands
Vec3 from = BodyPoints.chest(target), to = BodyPoints.chest(caster);
int ticks = Fx.travel(from, to, 0.8);             // how long the trip takes at 0.8 blocks a tick
Fx.fly(level, MyMod.id("mote"), from, to, ticks,
        1.5,                                      // it rises 1.5 blocks in the middle of the arc
        Fx.Fallback.line(ParticleTypes.END_ROD),
        () -> Heals.heal(caster, caster, 2));     // runs on the tick it lands

For a thrown entity, play a trail on it instead (Props › Flying).

Sounds and repeated effects#

Fx.sound(level, pos, sound, volume, pitch) and Fx.sound(entity, sound, volume, pitch) play a sound for everyone near enough to hear it, as a player's sound. Both take a SoundEvent or a Holder<SoundEvent>. Pass a SoundSource after the sound to put it on another volume slider, for example HOSTILE for a monster's attack.

Fx.onFor(entity, id, scale, fallback, every, ticks) plays an effect on an entity now and again every every ticks for ticks, for something that lasts, such as a mark or an aura. It stops early when the entity dies or leaves, and returns the Scheduler task to stop it sooner.

// a brand that smoulders on the target for 10 seconds, with a hiss when it lands
Fx.onFor(target, MyMod.id("brand"), 1, Fx.Fallback.burst(ParticleTypes.FLAME, 0.4f, 6),
        20, 200);                 // played again every 20 ticks for 200 ticks
Fx.sound(target, SoundEvents.FIRECHARGE_USE, 0.8f, 1.2f);   // volume 0.8, pitch 1.2

Player animations#

PlayerAnims plays Player Animation Library animations from the server, shown to the player and everyone who can see them. It can also run code at set points of an animation and end it early (Cues and stop conditions).

CallDoes
PlayerAnims.play(entity, id)plays animation id on a player, blending in over 3 ticks. Any other entity is skipped, so abilities call it for every caster
PlayerAnims.hold(entity, id)the same for a looping animation, and players who come into view while it loops are shown it too
PlayerAnims.stop(entity)eases the player back to standing (through dicelib:rest)

An id like mymod:sword.slash names the animation sword.slash in any file under assets/mymod/player_animations/. The file name doesn't matter. Files use Blockbench's bedrock animation format with the player's bones: head, body, right_arm, left_arm, right_leg and left_leg. The player faces -Z with the right arm at +X, so an arm at x rotation -90 points forward, and at z 90 (right arm) or -90 (left arm) it points out to the side. Bones the animation doesn't name keep moving normally, so a cast that moves only the arms still walks.

An animation with "loop": true plays until replaced or stopped, which is how a charge holds a pose. Start a looping animation with hold. play only reaches the players watching at that moment, so someone who walks up later would see the caster standing still. The client keeps one animation layer for DiceLib at priority 1500, the library's range for gameplay animations, above emotes. It shows the arms in first person, so casts look right there too.

// a stance held while a shield is raised, and dropped with it
PlayerAnims.hold(player, MyMod.id("shield.raise"));
// ... later
PlayerAnims.stop(player);

Cues and stop conditions#

PlayerAnims.of(entity, id) sets an animation up with more control, and play() starts it. Use it when the ability needs to act at a certain point of the animation, or when something should cut the animation short.

// a 3 second channel that pulses every second and releases at the end
PlayerAnims.of(caster, MyMod.id("staff.channel"))
        .looping()                // the animation file loops, and players who arrive later are shown it too
        .length(60)               // the server counts it as over after 60 ticks
        .at(20, entity -> pulse(entity))          // cues, in server ticks from the start
        .at(40, entity -> pulse(entity))
        .stopWhenHurt()           // ends it early with End.HURT
        .stopWhenMoving()         // ends it early with End.MOVED
        .onEnd((entity, end) -> {
            // DONE means it ran its full length. Any other reason means the channel was lost.
            if (end == PlayerAnims.End.DONE) release(entity);
        })
        .play();
CallDoes
speed(factor)plays it faster or slower (2 is double speed)
fadeIn(ticks)how long it blends in (3 by default, 0 snaps)
mirrored()swaps left and right, so one animation works for both hands
looping()the same as hold: players who come into view later are shown it
length(ticks)how long the server counts it as playing. Without it the animation never reports DONE
at(tick, entity -> ...)runs on the server that many ticks after the start (0 is immediately), if it is still playing
stopWhenHurt()ends it when the entity takes damage
stopWhenMoving()ends it once the entity is more than half a block from where it started
stopOnItemSwap()ends it when the main hand holds a different item
stopWhen(entity -> ...)ends it on the first tick the condition is true
onEnd((entity, end) -> ...)runs once however it stops, with the reason

End is DONE (the length ran out), STOPPED (stop was called), REPLACED (another animation started), HURT, MOVED, SWAPPED, CONDITION, or GONE (the entity died or left).

The server can't read animation files, so length and the cue ticks are numbers you supply. They are server ticks and don't change with speed. play() returns a Playing handle with id(), tick(), isPlaying() and stop(), and PlayerAnims.playing(entity) returns the current one. PlayerAnims.stop(entity, fadeOut) stops with a blend-out time of your choice.

Only players animate. For a mob the animation is skipped, but the cues, the stop conditions and onEnd still run, so the ability behaves the same for every caster.

The library's own documentation is at docs.zigythebird.com/pal/intro.

Body Parts

Body parts are GeckoLib models drawn on players, such as wings, horns or a tail. They are drawn by the player renderer over armor, so everyone sees them, and each player's copy animates on its own. Everything here is client side, in client.render.bodypart, registered at client setup (FMLClientSetupEvent).

Setting them up takes three calls:

PieceSays
BodyParts.register(part)defines a part, with its model and how it moves
BodyParts.add(group, uses...)which parts a group wears. A group is any id, such as a race or a class
BodyParts.setSource(player -> worn)what each player wears right now, and in what look. DiceLib draws what it returns

Parts are not drawn on invisible players. Each player can also choose whose parts are drawn with the client option bodyParts.show in config/dicelib-client.toml, which is ALL, OTHERS (everyone except themselves) or NONE.

Parts#

A part with id ns:name uses these files:

assets/ns/textures/bodypart/name_mark_<marking>.pngone per marking, drawn over the colour
@EventBusSubscriber(modid = MyMod.MODID, value = Dist.CLIENT, bus = EventBusSubscriber.Bus.MOD)
public final class ExampleParts {
    public static final ResourceLocation HORNS = MyMod.id("horns");
    public static final ResourceLocation WINGS = MyMod.id("wings");
    public static final ResourceLocation TAILS = MyMod.id("tails");

    @SubscribeEvent
    static void setup(FMLClientSetupEvent event) {
        // The parts. Each id names a model made in Blockbench.

        // Horns sit on the head, which is the default. anchor is the point a size option scales around, here 28
        // pixels up in the model. The two fidgets are animations played now and then while the player rests.
        BodyParts.register(BodyPart.builder(HORNS).anchor(28, 0).fidgets("fidget_tilt", "fidget_nod").build());
        // Wings sit on the body. flight picks the loop from how the player moves: "glide" while gliding, "flap"
        // while rising, "idle" otherwise. The sixfold shape has its own fidget animations.
        BodyParts.register(BodyPart.builder(WINGS).on(BodyPart.Attach.BODY).anchor(20, 2.5f)
                .loop("idle", BodyPart.flight("idle", "glide", "flap"))
                .fidgets("fidget_stretch", "fidget_ruffle")
                .shapeAnimations("sixfold", "fidget_sixfold_left", "fidget_sixfold_right")
                .build());
        // Tails: the model has bones tail_1 to tail_9. fan shows as many as the wearer's count says and spreads
        // them 13 degrees apart, lifted by -55 degrees.
        BodyParts.register(BodyPart.builder(TAILS).on(BodyPart.Attach.BODY).loop("sway").anchor(12, 2)
                .bones(BodyPart.fan("tail_", 9, 13, -55)).build());

        // Which group wears which parts. A group is any id you choose.
        BodyParts.add(MyMod.id("demon"), BodyParts.use(HORNS));                    // a whole race
        BodyParts.add(MyMod.id("wyrmkin/elder"), BodyParts.use(TAILS, 9));         // one lineage, nine tails
        BodyParts.add(MyMod.id("wyrmkin"), BodyParts.use(TAILS, 3), BodyParts.use(WINGS));

        // A group with no parts uses its parent's. Here the parent is the id with its last "/part" cut off, so
        // mymod:wyrmkin/young falls back to mymod:wyrmkin. Returning null means there is no parent.
        BodyParts.setParent(id -> {
            String path = id.getPath();
            return path.contains("/") ? id.withPath(path.substring(0, path.lastIndexOf('/'))) : null;
        });

        // What each player wears right now. This runs on the client for every player it draws. Here a
        // player's group is their scoreboard team's name. A real mod reads its own synced data instead.
        BodyParts.setSource(player -> {
            if (player.getTeam() == null) return List.of();
            ResourceLocation group = MyMod.id(player.getTeam().getName());
            // the look: colour, whether the colour is rare, markings, whether those are rare, shape, scale
            BodyParts.Look look = new BodyParts.Look("crimson", false, "none", false, "ram", 1);
            return BodyParts.wear(BodyParts.of(group), look);
        });
    }

    private ExampleParts() {
    }
}

Groups#

BodyParts.add(group, BodyParts.use(part), BodyParts.use(part, count)...) gives a group its parts, replacing any it had, and BodyParts.remove(group) takes them away. BodyParts.of(group) reads them back: the group's own, else its parent's, and so on up. BodyParts.setParent(id -> parent) says what a group's parent is, returning null at the top. If it is never set, no group has a parent.

What each player wears#

Dialogue

DiceLib has two ways to make characters talk. Speech shows a spoken line to the players near a speaker, as a subtitle above the hotbar and optionally as a bubble over the speaker's head. Dialogues runs conversation trees from datapack files. One player picks the choices in a box along the bottom of the screen, the server runs the actions those choices call, and nearby players can overhear the lines. Both are in dialogue and run on the server. How they look comes from a look or a custom UI (Looks and Custom UIs).

Spoken lines#

Speech.of(entity, text) makes a line said by an entity. The entity's name shows above the text, range is measured from it, and bubble() puts a bubble over its head. Speech.of(name, text) makes a line with no body, heard around a spot (at(level, pos)) or by the players named (to(players)). send() sends it and returns who got it.

public final class BossTaunts {
    // A panel for the fight, shown to everyone within 48 blocks. Keep what show() returns to change it later.
    public static MobPanel showPanel(LivingEntity boss) {
        return MobPanels.on(boss)
                .range(48)
                .pinned(MobPanels.Corner.TOP_LEFT)        // fixed in a screen corner, with a line down to the boss
                .title(Component.literal("The Hollow King"))
                .icon(new ItemStack(Items.WITHER_SKELETON_SKULL))
                .health()                                 // a health bar that each client fills in from the boss itself
                .line("phase", Component.literal("Phase 1"))                  // "phase" is the key used to change it
                .bar("rage", Component.literal("Rage"), 0, 100, 0xFFC03030)   // starts at 0 of 100, in red
                .show();
    }

    // The fight opens with a line in the subtitle box and a bubble over the boss, heard within 32 blocks.
    public static void opening(LivingEntity boss) {
        Speech.of(boss, Component.literal("Another crown-seeker. Kneel, or be knelt."))
                .bubble()
                .voice(SoundEvents.WITHER_AMBIENT, 1.4f)  // a soft sound as the text types, at pitch 1.4
                .send();
    }

    // At half health. interrupt() cuts off a line that is still typing, where a normal line would wait its turn.
    public static void phaseTwo(LivingEntity boss, MobPanel panel) {
        Speech.of(boss, Component.literal("Enough. No more holding back."))
                .range(48).bubble().interrupt().voice(SoundEvents.WITHER_AMBIENT, 1.1f).send();
        // the same keys as above. Both changes go out to viewers together at the end of the tick
        panel.set("phase", Component.literal("Phase 2")).bar("rage", 100);
    }
}

Dialogue trees#

A tree is a JSON file at data/<namespace>/dicelib/dialogues/<path>.json, and its id is <namespace>:<path>. A tree is made of nodes. A node shows its lines one after another, runs its actions as it opens, then offers its choices. A node without choices moves on to next, or ends the conversation.

Placeholders#

Words in braces are filled in on the server as each line goes out. {player} and {speaker} become the names. They work in plain strings, in "text" objects and in a translation's "with" arguments. A translated line keeps %s in its lang file and puts the placeholder in "with":

{"translate": "dialogue.mymod.toll", "with": ["{player}", "{mymod:coins}"]}

Dialogues.placeholder(name, (player, speaker) -> ...) adds your own. Call it once at startup. The function returns the text for the player the line goes to, or null to leave the placeholder as written. Names are lower case, and yours should start with your mod id. A name nobody registered stays in the line, braces and all.

Dialogues.placeholder("mymod:coins", (player, speaker) -> Component.literal(String.valueOf(Coins.of(player))));

The screen#

The box sits along the bottom of the screen and the game keeps running behind it. Each line types out. A click, Space or Enter finishes the line, then shows the next. After the last line the choices appear: click one, or press 1 to 9. Escape closes the box when the node allows it. A tree whose style names a custom dialogue UI opens that screen instead (Looks and Custom UIs › Dialogue). Every answer carries the number of the step it was given for, and the server ignores an answer for any other step, so a double click or a late click does nothing.

@EventBusSubscriber(modid = MyMod.MODID)
public final class FerrymanDialogue {
    // the tree in data/mymod/dicelib/dialogues/example/ferryman.json
    public static final ResourceLocation TREE = MyMod.id("example/ferryman");

    // Call once from the mod constructor. It registers an action and a condition that the tree's JSON names by id.
    public static void init() {
        // An action runs on the server when a node is entered or a choice is picked.
        // In the JSON: {"id": "mymod:example_ferry_ticket"}
        UiActions.action(MyMod.id("example_ferry_ticket"), (player, context, args) -> {
            ItemStack ticket = new ItemStack(Items.PAPER);
            ticket.set(DataComponents.CUSTOM_NAME, Component.literal("Ferry Ticket"));
            player.getInventory().add(ticket);
        });
        // A condition decides whether a choice is offered. In the JSON: {"id": "mymod:example_is_night"}
        UiActions.condition(MyMod.id("example_is_night"), (player, context, args) -> player.level().isNight());
    }

    // From now on a right-click on this entity starts the tree. The binding is saved with the entity.
    public static void hire(Entity ferryman) {
        Dialogues.bind(ferryman, TREE);
    }

    // DialogueEvent.End fires however a conversation ends. This one only answers a player who walked out of range.
    @SubscribeEvent
    static void onEnd(DialogueEvent.End event) {
        if (event.getSession().tree().id().equals(TREE) && event.getReason() == EndReason.TOO_FAR) {
            event.getServerPlayer().sendSystemMessage(Component.literal("The ferryman shrugs and goes back to his oars."));
        }
    }
}

Holograms

A hologram is a panel floating in the world that only chosen players see. Two audiences decide who: viewers see it, and interactors may press its buttons. Everyone viewing sees the same content, and a change reaches all of them together. A player presses a button by aiming at it and right-clicking. A mob panel is the HUD equivalent. It is a small panel tied to a mob, shown either beside the mob in brackets or pinned to a corner of the screen with a line leading to the mob. Both are in hologram and run on the server, and the client only draws what the server sends.

A hologram#

Holograms.at(level, pos) starts one at a point (the middle of the panel), and spawn() shows it. content(p -> ...) lists the parts from top to bottom.

public final class PartyBoard {
    // A board on a wall. Players tagged "party" see it and can press its buttons. Operators see it too but can't
    // press anything. Anyone in the party can leave, and only a player flagged as leader can open the way down.
    public static Hologram open(ServerLevel level, Vec3 wall) {
        // arguments for two built-in UiActions, written the way a JSON file would give them
        JsonObject leave = new JsonObject();
        leave.addProperty("command", "tag @s remove party");          // dicelib:command runs this as the presser
        JsonObject leader = new JsonObject();
        leader.addProperty("flag", "party_leader");                   // dicelib:flag passes for players with the flag
        return Holograms.at(level, wall)
                .facing(Direction.NORTH)                  // fixed, like a sign
                .width(150)                               // GUI pixels across
                .range(16)                                // seen from up to 16 blocks away
                .viewers(Audience.anyOf(Audience.tagged("party"), Audience.permission(2)))   // the party, and operators
                .interactors(Audience.tagged("party"))                                       // only the party presses
                .content(p -> p.title(Component.literal("Drowned Halls"))
                        .text("party", Component.literal("Party: 1/4"))    // "party" is the key joined() changes
                        .divider()
                        // greyed out for a viewer unless every condition in the list passes for them
                        .button("descend", Component.literal("Descend"), PartyBoard::descend, List.of(UiActions.ref("dicelib:flag", leader)))
                        // this button runs a UiActions call where the others run Java code
                        .button("leave", Component.literal("Leave the party"), UiActions.ref("dicelib:command", leave)))
                .spawn();
    }

    // Changes one line by its key. Everyone looking at the board sees the new text.
    public static void joined(Hologram board, int members) {
        board.text("party", Component.literal("Party: " + members + "/4"));
    }

    // update replaces the whole panel, so the buttons are gone afterwards
    private static void descend(ServerPlayer leader, Hologram board) {
        board.update(p -> p.title(Component.literal("Drowned Halls")).text(Component.literal("The way down is open.")));
    }
}

Viewers are worked out again every 10 ticks, so a player who walks into range or gains a tag starts seeing it then. Changing the audience takes effect immediately. Past 48 blocks a client stops drawing a hologram and frees its texture.

Facing#

A hologram either turns or stays put.

Going away on its own#

A hologram made in code lasts until remove() or until the server stops, and a saved one lasts until remove(). Four builder options remove a hologram automatically. You can combine them, and whichever triggers first removes it.

Builder callTakes it away when
lifetime(ticks)that many ticks have passed since it spawned
idleTimeout(ticks)that many ticks pass without anyone pressing a button. Every press starts the count again
tiedTo(player)the player logs out. A saved hologram waits for them to come back instead
tiedTo(player, condition)the same, and also as soon as the condition fails for the player. The condition is a UiActions call (Dialogue › Actions and conditions), so a saved hologram keeps it

The server checks timers and ties every 10 ticks. On a spawned hologram, lifetime(ticks) and idleTimeout(ticks) set a timer again, counted from now (0 turns it off). keepAlive() starts the idle count again, for interaction the hologram can't see, such as a player answering in chat. expiresIn() gives the ticks until a timer takes it away (-1 for never), for a countdown on the panel. tie() gives the player and condition it belongs to. Saved holograms keep their timers and ties through restarts, and their clocks stand still while the server is down.

public final class PathChoice {
    // A menu in front of one player that only they see. It belongs to a quest step: it closes when the player's
    // "on_crossroads_quest" flag is cleared, and by itself after 30 seconds untouched.
    public static Hologram open(ServerPlayer player) {
        Vec3 eyes = player.getEyePosition();
        // two blocks ahead at eye height: the look direction flattened, made one block long, then doubled
        Vec3 spot = eyes.add(player.getLookAngle().multiply(1, 0, 1).normalize().scale(2));
        // the arguments of the built-in dicelib:flag condition, written the way a JSON file would give them
        JsonObject quest = new JsonObject();
        quest.addProperty("flag", "on_crossroads_quest");
        return Holograms.at(player.serverLevel(), spot)
                .facingToward(eyes)                       // turned to the player once. It doesn't follow them
                .viewers(Audience.players(player))        // nobody else sees it
                .idleTimeout(600)                         // removed after 30 seconds with no button pressed
                // removed as soon as the condition fails for the player, which is when the flag is cleared
                .tiedTo(player, UiActions.ref("dicelib:flag", quest))
                // a button has an id, a label, and the code a press runs on the server
                .content(p -> p.title(Component.literal("Choose a path"))
                        .button("left", Component.literal("Left"), (chooser, menu) -> choose(chooser, menu, "left"))
                        .button("right", Component.literal("Right"), (chooser, menu) -> choose(chooser, menu, "right")))
                .onRemove((menu, reason) -> {
                    // only the timeout gets a message. Picking a path closes the menu without one
                    if (reason == Hologram.RemoveReason.IDLE) player.sendSystemMessage(Component.literal("The choice fades."));
                })
                .spawn();
    }

    private static void choose(ServerPlayer player, Hologram menu, String path) {
        player.sendSystemMessage(Component.literal("You take the " + path + " path."));
        UiActions.setFlag(player, "on_crossroads_quest", false);   // the quest step is over
        menu.remove();
    }

    private PathChoice() {
    }
}

Clicks#

A right-click counts only when every check passes on the server: the hologram is still there and unchanged since the player saw it, the player is viewing it, may press it and stands close enough (aiming reaches 8 blocks), and the button exists with its conditions passing. Then Holograms.HologramEvent.Click fires (cancellable, getButton(), getHologram()), and the button runs. A right-click anywhere on a panel never reaches the block behind it. Saved holograms and templates#

Looks and Custom UIs

DiceLib draws its holograms, mob panels, dialogue box, subtitles and speech bubbles with plain GuiGraphics calls, as vanilla screens do, so it needs no UI library. Each of those surfaces names a style, which is an id such as dicelib:default, and each client looks that id up in two places:

  1. A custom UI registered for that surface under the id (CustomUis). If there is one, it draws the surface.
  2. Otherwise a look (Looks), which sets the colours and backgrounds of DiceLib's own UI.

An id with neither falls back to dicelib:default, so a typo shows the plain look. The ids are in ui.UiLooks so that server code can name them. Looks and custom UIs are in client.ui and are registered on the client at setup (FMLClientSetupEvent).

Hologram screens#

To build a hologram the way you build a vanilla Screen, extend HologramScreen (in client.hologram). Override init() and add widgets, draw your own background, and the crosshair works as the mouse. Vanilla widgets such as Button, EditBox and Checkbox work as they are. A left or right click presses the widget under the crosshair, and the scroll wheel reaches the screen while you aim at it.

public final class ShopScreen extends HologramScreen {
    public static final ResourceLocation ID = MyMod.id("shop");
    private static final ResourceLocation BACKGROUND = MyMod.id("textures/gui/shop.png");
    private EditBox amount;

    // Register at client setup: CustomUis.hologram(ShopScreen.ID, ShopScreen::new);
    public ShopScreen(HologramPayload hologram) {
        super(hologram, 176, 96);                         // the screen's size in GUI pixels
    }

    // Runs once before the first draw. Widgets are placed in GUI pixels from the screen's top left.
    @Override
    protected void init() {
        // a text box. A click on it gives it the keyboard until Enter, Escape or another click
        amount = addRenderableWidget(new EditBox(font, 8, 44, 60, 18, Component.literal("Amount")));
        amount.setValue("1");
        addRenderableWidget(Button.builder(Component.literal("Buy"), button -> {
            CompoundTag order = new CompoundTag();
            order.putString("amount", amount.getValue());
            send("buy", order);                           // goes to the hologram's onMessage on the server
        }).bounds(76, 43, 50, 20).build());
        // press("leave") presses the panel button with that id, as a click on DiceLib's own panel would
        addRenderableWidget(Button.builder(Component.literal("Leave"), button -> press("leave")).bounds(8, 70, 50, 20).build());
    }

    // Drawn under the widgets every time the screen redraws.
    @Override
    protected void renderBackground(GuiGraphics graphics, int mouseX, int mouseY, float partialTick) {
        graphics.blit(BACKGROUND, 0, 0, 0, 0, width, height, 256, 256);
        graphics.drawString(font, "Ferry tickets", 8, 8, 0xFF3A2A0A, false);
        // data() is the tag the server sent, with this player's own coins in it
        graphics.drawString(font, "Coins: " + data().getInt("coins"), 8, 24, 0xFF5A3A0A, false);
    }
}

Register it at client setup with CustomUis.hologram(ShopScreen.ID, ShopScreen::new).

A hologram is drawn into a texture, so it only redraws when the crosshair moves on it, after a click, or when you call redraw(). Sliders take their value from where you click them, because there is no dragging. A hologram has no keyboard focus, so a click on a text box opens a see-through typing screen that passes the keys to it.

The server still decides what a screen is allowed to do. press goes through the same checks as any hologram button. A message from send only arrives when the player is a viewer and an interactor of the hologram and stands within reach. The action and the tag are chosen by the client, so check them like any other input:

public final class ShopCounter {
    private static final String COINS = "mymod_coins";

    // The server side of ShopScreen. The style id picks the screen on each client, the panel holds the one button
    // the screen presses through the normal checks, and onMessage receives what the screen sends.
    public static Hologram open(ServerLevel level, Vec3 at, ServerPlayer customer) {
        Hologram shop = Holograms.at(level, at).style(MyMod.id("shop"))
                .content(p -> p.button("leave", Component.literal("Leave"), (player, hologram) -> hologram.remove()))
                .onMessage(ShopCounter::message)
                .spawn();
        showCoins(shop, customer);
        return shop;
    }

    // Runs when a client's ShopScreen calls send(action, data). The action and the tag are chosen by the client, so
    // every value is checked here before anything is given.
    private static void message(ServerPlayer player, Hologram shop, String action, CompoundTag data) {
        if (!action.equals("buy")) return;
        int amount;
        try {
            amount = Integer.parseInt(data.getString("amount"));     // the text box can hold anything
        } catch (NumberFormatException e) {
            return;
        }
        int coins = player.getPersistentData().getInt(COINS);
        if (amount < 1 || amount > 64 || amount > coins) return;      // no free or negative orders
        player.getPersistentData().putInt(COINS, coins - amount);
        player.getInventory().add(new ItemStack(Items.PAPER, amount));
        showCoins(shop, player);                                      // the screen redraws with the new total
    }

    // data(player, tag) sends a tag to one viewer only, so each player sees their own coins on the same hologram
    private static void showCoins(Hologram shop, ServerPlayer player) {
        CompoundTag own = new CompoundTag();
        own.putInt("coins", player.getPersistentData().getInt(COINS));
        shop.data(player, own);
    }

    private ShopCounter() {
    }
}

hologram.data(tag) sends new data to every viewer, and hologram.data(player, tag) lays data over it for one viewer alone. Saved holograms can't have an onMessage listener. Listen for Holograms.HologramEvent.Message instead, which fires for every message (getAction(), getData()) and can be cancelled.

Command Framework

Commands are annotated classes, and the framework builds the Brigadier trees from them. The annotations live inside CommandRegistry (package org._50dozenhits.dice_library.command), so a command class imports them from there: import org._50dozenhits.dice_library.command.CommandRegistry.Execute;. It builds the trees on every RegisterCommandsEvent (server start and /reload).

@Command("heal")
@Permission(value = "mymod.heal", permissionLevel = Permission.PermissionLevel.GAMEMASTER)
public class HealCommand {
    @Execute                                                          // /heal
    public boolean self(@SenderArg ServerPlayer player) {
        player.setHealth(player.getMaxHealth());
        return true;
    }

    @Execute                                                          // /heal <target> <amount>
    public boolean other(@EntityArg(name = "target", value = EntityArg.Type.PLAYER) ServerPlayer target,
                         @FloatArg(min = 0) float amount) {
        target.heal(amount);
        return true;
    }
}

Register it once in the mod constructor:

CommandRegistry.registerCommand(HealCommand.class);

Classes and methods#

AnnotationOnMeaning
@Command(value, subCommands)classone literal per value (aliases). subCommands are child classes, each with their own @Command
@Executemethodan executor. Its annotated parameters become the argument chain under the class's literal
@Permission(value, permissionLevel)class or methodwho may use it (Permissions)

The rules:

  • An executor returns boolean (true = 1, false = 0), int (passed through) or void (1).
  • Every parameter needs @SenderArg or an argument annotation that matches its type. A mismatch throws at server start, naming the class and method.
  • A method with only @SenderArg parameters runs on the class's literal itself. A class has at most one.
  • Classes, constructors and methods may be private, because the framework makes them accessible. Each class needs a no-arg constructor.
  • Register only the root class, with CommandRegistry.registerCommand from the mod constructor. It checks the class tree immediately and creates the permission nodes.
  • Brigadier merges executors that share leading nodes (like grant <targets> <item> and grant <targets> <item> <count>).

A command tree#

This example has nested classes, aliases, a literal with two values, an enum, and an optional last argument written as two executors that share a prefix:

@Command(value = {"soulforge", "sf"}, subCommands = {SoulforgeCommand.Status.class, SoulforgeCommand.Tune.class})
@Permission(value = "mymod.soulforge", permissionLevel = Permission.PermissionLevel.PLAYER)
public class SoulforgeCommand {
    public enum Element { METAL, STEAM, INK }

    // /soulforge  (and /sf)
    @Execute
    public boolean help(@SenderArg CommandSourceStack source) {
        source.sendSuccess(() -> Component.literal("Use /soulforge status or /soulforge tune"), false);
        return true;
    }

    @Command("status")
    public static class Status {
        // /soulforge status
        @Execute
        public boolean self(@SenderArg ServerPlayer player) {
            player.sendSystemMessage(Component.literal("Level " + player.experienceLevel));
            return true;
        }

        // /soulforge status <player>
        @Execute
        @Permission(value = "mymod.soulforge.status.others", permissionLevel = Permission.PermissionLevel.GAMEMASTER)
        public boolean other(@SenderArg CommandSourceStack source,
                             @EntityArg(name = "player", value = EntityArg.Type.PLAYER) ServerPlayer player) {
            source.sendSuccess(() -> Component.literal(player.getScoreboardName() + ": level " + player.experienceLevel), false);
            return true;
        }
    }

    @Command("tune")
    public static class Tune {
        // /soulforge tune up <amount>   and   /soulforge tune down <amount>
        @Execute
        public int shift(@SenderArg ServerPlayer player, @LiteralArg({"up", "down"}) String direction,
                         @IntegerArg(min = 1, max = 10) int amount) {
            int delta = direction.equals("up") ? amount : -amount;
            player.giveExperienceLevels(delta);
            return player.experienceLevel;             // the int becomes the command result
        }

        // /soulforge tune element <metal|steam|ink>
        @Execute
        public boolean element(@SenderArg ServerPlayer player, @LiteralArg("element") String literal, @EnumArg Element element) {
            player.getPersistentData().putString("mymod_tuned", element.name());
            return true;
        }

        // /soulforge tune name <word>   and   /soulforge tune name <word> <times>
        @Execute
        public boolean name(@SenderArg ServerPlayer player, @LiteralArg("name") String literal, @TextArg(name = "word") String word) {
            return name(player, literal, word, 1);
        }

        @Execute
        public boolean name(@SenderArg ServerPlayer player, @LiteralArg("name") String literal, @TextArg(name = "word") String word,
                            @IntegerArg(value = "times", min = 1, max = 5) int times) {
            player.sendSystemMessage(Component.literal(word.repeat(times)));
            return true;
        }
    }
}

Errors#

  • A CommandSyntaxException thrown by an executor shows the player a red error, as a vanilla command does.
  • Any other exception is logged with the method name, and the sender sees "The command failed: <message>" with a result of 0.
@Command("refund")
public class RefundCommand {
    private static final SimpleCommandExceptionType NOTHING_SPENT =
            new SimpleCommandExceptionType(Component.literal("Nothing to refund"));
    private static final DynamicCommandExceptionType TOO_MUCH =
            new DynamicCommandExceptionType(amount -> Component.literal("Can't refund " + amount));

    @Execute
    public boolean refund(@SenderArg ServerPlayer player, @IntegerArg(min = 1) int amount) throws CommandSyntaxException {
        // levels spent at the forge, counted in the player's saved data
        int spent = player.getPersistentData().getInt("mymod_spent");
        if (spent == 0) throw NOTHING_SPENT.create();                 // shows as a red message
        if (amount > spent) throw TOO_MUCH.create(amount);            // shows as a red message
        player.getPersistentData().putInt("mymod_spent", spent - amount);
        player.giveExperienceLevels(amount);
        return true;
    }
}

Optional arguments and suggestions#

@OptionalArg next to a parameter's argument annotation lets the command run without it, and without every parameter after it, which must be optional too. A left-out parameter arrives as null (0 or false for a primitive), so use Integer, Boolean and so on where "not given" differs from 0.

// /coins give 5        /coins give 5 quest        /coins give 5 quest 3
@Execute
public boolean give(@SenderArg ServerPlayer player, @LiteralArg("give") String literal, @IntegerArg(min = 1) int amount,
                    @OptionalArg @TextArg String reason, @OptionalArg @IntegerArg Integer times) {
    int repeats = times == null ? 1 : times;
    // ...
    return true;
}

Optional parameters are left out from the end, so /coins give 5 3 reads 3 as the reason. Arguments that can each be given alone still need a method per form.

@Suggest sets what tab completion offers for a parameter. Give it fixed values, or a provider class with a no-arg constructor when the values have to be worked out at the time. Players can still type anything, so check the value.

@Suggest({"red", "green", "blue"}) @TextArg String colour
@Suggest(from = OnlineGuilds.class) @TextArg String guild     // class OnlineGuilds implements SuggestionProvider<CommandSourceStack>

Permissions#

@Permission("modid.path") becomes a NeoForge permission node, registered in PermissionGatherEvent.Nodes. The part before the first dot is the node's namespace, so the framework refuses a value with no dot. When two annotations use the same node, the first one's level wins.

A sender with the vanilla permission level may run the command. A player without the level still may when NeoForge's PermissionAPI grants the node, which is how permission mods hand out single commands.

Placed onApplies to
a classits literal and everything under it. Hidden from tab completion when not allowed
a methodthe method's first argument node (hidden when not allowed), checked again when the command runs
neither, on a class with sub commands and nothing to run itselfshown only to senders who can use something under it

The run time check means a method permission still works on an executor with no arguments, and when another method shares the first node.

The last row suits an admin branch such as /mymod admin. The branch has no node, but every command in it does, so a player granted one command sees the branch holding that one command.

@Command("warden")
@Permission(value = "mymod.warden", permissionLevel = Permission.PermissionLevel.PLAYER)
public class WardenCommand {
    // everyone: /warden
    @Execute
    public boolean info(@SenderArg CommandSourceStack source) {
        return true;
    }

    // ops only: /warden summon <pos>, hidden from everyone else
    @Execute
    @Permission(value = "mymod.warden.summon", permissionLevel = Permission.PermissionLevel.GAMEMASTER)
    public boolean summon(@SenderArg CommandSourceStack source, @LiteralArg("summon") String l, @BlockPosArg BlockPos pos) {
        Warden warden = EntityType.WARDEN.create(source.getLevel());
        if (warden == null) return false;
        warden.moveTo(pos.getX() + 0.5, pos.getY(), pos.getZ() + 0.5, 0, 0);
        return source.getLevel().addFreshEntity(warden);
    }
}

A permission mod like LuckPerms grants mymod.warden.summon to a single player without making them op.

Custom argument types#

Register a factory for an annotation plus a Java type, before the first command build (the mod constructor is safe). The factory runs once for every place the parameter appears in the tree, so it creates new node builders every time.

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.PARAMETER)
public @interface ElementArg {
    String value() default "element";
}
public enum ExampleElement {
    METAL, STEAM, INK, MUSIC;

    public String id() {
        return name().toLowerCase(Locale.ROOT);
    }
}
public final class ExampleArguments {
    private static final DynamicCommandExceptionType UNKNOWN =
            new DynamicCommandExceptionType(id -> Component.literal("Unknown element " + id));

    // call from the mod constructor, before CommandRegistry.registerCommand
    public static void register() {
        CommandRegistry.registerArgument(ElementArg.class, ExampleElement.class, (arg, handler) -> {
            String name = handler.name(arg.value());
            handler.addNode(Commands.argument(name, StringArgumentType.word())
                    .suggests((context, builder) -> SharedSuggestionProvider.suggest(
                            Arrays.stream(ExampleElement.values()).map(ExampleElement::id), builder)));
            handler.addValueExtractor(context -> {
                String typed = StringArgumentType.getString(context, name);
                for (ExampleElement element : ExampleElement.values()) {
                    if (element.id().equals(typed)) return element;
                }
                throw UNKNOWN.create(typed);           // red error for the player
            });
        });
    }
}
@Command("attune")
public class AttuneCommand {
    // /attune <element>, with suggestions
    @Execute
    public boolean attune(@SenderArg ServerPlayer player, @ElementArg ExampleElement element) {
        player.sendSystemMessage(Component.literal("Attuned to " + element.id()));
        return true;
    }
}

A factory can also add several alternative nodes, each with its own value, as @LiteralArg does. A boolean parameter typed as on or off:

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.PARAMETER)
public @interface OnOffArg {
}
CommandRegistry.registerArgument(OnOffArg.class, boolean.class, (arg, handler) -> {
    handler.addNode(Commands.literal("on"));
    handler.addValueExtractorToLastNode(context -> true);
    handler.addNode(Commands.literal("off"));
    handler.addValueExtractorToLastNode(context -> false);
});

ArgumentNodeHandler methods:

MethodUse
addNode(builder)a node for the parameter. Adding several makes alternative branches
addValueExtractor(context -> value)how to read the value, for every branch without its own. May throw CommandSyntaxException
addValueExtractorToLastNode(context -> value)a value for the branch just added. This is how @LiteralArg knows which literal was typed

A later registration for the same annotation and type beats an earlier one, built-ins included. Lookup tries the exact type first, then registered supertypes, which is how @EnumArg handles every enum.
